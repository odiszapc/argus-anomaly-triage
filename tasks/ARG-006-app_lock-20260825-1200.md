# ARG-006 · Блокировки приложения: «Timeout <N> wait exceeded» на 226 хостах, повторяется с 25.08

**Исполнитель:** Backend Lead · **Severity:** SEV-1 · **Начало:** 25.08 12:00 UTC · **Обнаружено:** 25.08 12:10 (через 20 мин) · **Закрыт:** 25.08 15:00

## Что происходит

С 25.08 15:00 ошибка ожидания блокировки «Timeout <N> wait exceeded» идёт волнами. Последняя волна началась 26.08 11:10, пик — 39 818 строк за 10 мин в 11:20 (обычно 21,5). Каждая волна задевает около 226 хостов одновременно. Вместе с ней растут таймауты внутреннего REST API: 95,2 тыс. строк, почти все 5xx. RPS (77 204 против 80 075 вчера) и трафик по странам в норме, CPU низкий (~18 %), поэтому причины на стороне инфраструктуры или нагрузки не видно. Это продолжение ARG-006 и ARG-003.

## Симптомы

- «Timeout <N> wait exceeded»: 199 030 строк с 26.08 11:10, пик 39 818 за 10 мин в 11:20; волны чередуются с почти пустыми бакетами (11–22 строки), каждая волна сразу на 224–227 хостах
- По суткам растёт: 31,7 тыс. (24.08) → 350 тыс. (25.08) → 538,9 тыс. (26.08 до 15:20)
- Одновременно «Rest error: Operation timed out after <N> milliseconds with <N> bytes received»: 95 231 строк, из них 94 598 — 5xx; также «GRPC invalid response code» — 15 475
- С 11:40 появились «Redis failure» (1 022) и «Unexpected Redis exception» (891), с 14:00 — «Privileges API not available» (534)
- RPS 77 204/с против 80 075/с вчера; CPU в окне 41,5 % против 59,2 %, после 11:00 держится на 16–20 %; латентность топ-эндпоинтов и трафик по странам на уровне вчерашнего
- Ошибки на 268 из 280 хостов, топ — kube0565–kube0569 (12,4–13,9 тыс. строк каждый), то есть равномерно по всему кластеру

## Возможные причины

1. **Регрессия в коде блокировок: много запросов конкурируют за одну блокировку и упираются в таймаут ожидания** — Сигнатура повторяется с 25.08 (ARG-006) и растёт день ко дню: 31,7 тыс. → 350 тыс. → 538,9 тыс. Волны синхронно затрагивают ~226 хостов. RPS и CPU не выросли, то есть всплески создаёт не нагрузка. _(уверенность: высокая)_
2. **Cache stampede: ключ с общим TTL истекает одновременно, и все поды разом идут его перестраивать под блокировкой** — Волны с паузами в одну 10-минутную корзину (11:10, 12:00, 12:30, 13:20, 14:00, 14:20, 14:40, 15:10), всплеск сразу на всех хостах. С 11:40 есть «Redis failure» и «Unexpected Redis exception», но их мало (около 1 тыс.), чтобы считать их причиной. _(уверенность: средняя)_
3. **Блокировки держатся дольше из-за медленного внутреннего REST API (entity list, Privileges): держатель блокировки ждёт ответа REST** — REST-таймауты начались в той же корзине 11:10 и дают почти все 5xx (94 598). На 25.08 их было 2,47 млн — тот же паттерн, что в ARG-003. По этим данным не видно, что началось раньше — REST или блокировки. _(уверенность: средняя)_
4. **Боты или атака** — Подтверждений нет: доля Reliance Jio 8,9 % против 10,6 % за прошлые сутки, трафик по странам в норме. _(уверенность: низкая)_
