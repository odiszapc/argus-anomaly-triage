# ARG-012 · Трафик из BR вырос в 1,9 раза с 09:20 при нормальных RPS, CPU и латентности

**Исполнитель:** SEO Specialist · **Severity:** SEV-3 · **Начало:** 03.09 09:30 UTC · **Обнаружено:** 03.09 11:20 (через 120 мин) · **Закрыт:** 04.09 08:20

## Что происходит

С 03.09 09:20 хиты из BR держатся на уровне ~1,8–2,0 тыс./с в 10-минутном окне при обычных 1052 (пик 2030, ×1,9); по окну BR 1835,4 против 898,3 вчера (×2,04). Общий RPS 86397,6 против 73616,2 вчера, CPU 22,5 % против 21,3 %, латентность топовых эндпоинтов не изменилась. Ошибок, связанных с инцидентом, нет; по данным это похоже на рост органического/внешнего трафика из одной страны, а не на отказ инфраструктуры.

## Симптомы

- metric_country BR: скачок с 996 (08:50) до 1796 (09:30), к 11:20 дорос до 2030 — выше максимума за последние две недели (1802,85 25.08)
- Отношение к вчерашнему окну по BR — 2,04; другие страны в норме (IN 0,95, US 0,93, BD 1,21, FR 1,23)
- RPS 86397,6 против 73616,2 вчера, CPU 22,5 % против 21,3 % — инфраструктура нагрузку держит
- Латентность эндпоинтов без изменений (максимальный рост mobile:traffic_stars:in — ×1,03)
- Ошибки из BR не растут вместе с трафиком: 6311 строк в 09:00, 1661 в 10:00, 439 в 11:00; в окне разбросаны по домашним провайдерам (Telefonica Brasil 755 строк / 733 IP, Claro NXT 693 / 676 IP)

## Возможные причины

1. **Рост поискового/реферального трафика из Бразилии (изменение позиций в Google, попадание в локальные подборки, внешние ссылки)** — Ступенчатый рост ровно в одной стране с 09:20, устойчиво держится 2 часа; трафик идёт с массовых провайдеров (Telefonica, Claro, Brasil Telecom), без всплеска ошибок и нагрузки на CPU _(уверенность: средняя)_
2. **Маркетинговая кампания или внешний источник трафика (соцсети, партнёрская закупка) на BR** — Резкая ступенька между 08:50 и 09:30 больше похожа на запуск кампании, чем на плавное органическое изменение; тот же паттерн, что в ARG-007 (CN ×2,6 при нормальных RPS/CPU) _(уверенность: средняя)_
3. **Бот-трафик или скрейпинг через бразильские резидентные IP** — Слабые признаки: в логах ошибок почти 1 строка на IP (733 IP на 755 строк у Telefonica), что бывает при ротации прокси, но и у обычных пользователей; концентрации на ASN хостинга нет — подтвердить нельзя без данных по User-Agent и эндпоинтам _(уверенность: низкая)_
